# Справочник техники по фракциям и меткам

Генератор `Generate entity labels snapshots` находится в категории `ME_Vehicle_Spawn/Entity Labels` плагинов World Editor тестового аддона.

Результат: `ME_Vehicle_Spawn_Test/Configs/Generated/ME_EditableEntityLabelsSnapshot.conf`.

Структура: `m_aScopes` (ключ фракции) → `m_aLabels` (имя метки) → `m_aPrefabs` (путь prefab с GUID). Контейнер техники называется по файлу без расширения, например `S1203_transport_red`. Недопустимые символы заменяются на `_`; совпадающие имена внутри группы получают суффиксы `_2`, `_3` в порядке отсортированных полных путей. Полный путь остаётся идентификатором техники.

Одна машина может присутствовать в нескольких группах меток. `__NO_LABELS__` — служебная группа техники без меток, а не значение EEditableEntityLabel. Индекс каталога и локализованное имя записи не сохраняются: они не нужны для сопоставления метки с prefab.

## Источник данных

Справочник отражает только VEHICLE-каталоги фракций открытого мира и активных зависимостей. Глобальный каталог не читается и не сохраняется. Это не перечень всех prefab базовой игры: отсутствующие в мире фракции не попадут в результат. Фракции без VEHICLE-каталога перечисляются в логе как SKIPPED.

Используются GetEditableEntityLabels у catalog entries, как в диагностике фильтра. Техника не создаётся. Повторные пути в одной группе меток объединяются.

## Запуск и проверка

1. Открыть только test addon, перезагрузить скрипты и открыть тестовый мир с FactionManager в Edit mode.
2. Запустить `Generate entity labels snapshots` через меню плагинов World Editor.
3. Дождаться `[ME_DEBUG_AVSP_WB] labels_snapshot status=SUCCESS` либо FAIL с причиной. Проверка повторяется до 5 секунд после запуска сборки; сообщение Build successful само по себе не подтверждает round-trip.
4. Открыть конфиг, проверить фракции, имена контейнеров техники и известные метки.
5. Повторить генерацию без изменений и проверить отсутствие diff конфигурации.

SUCCESS требует совпадения всех сохраняемых полей, размеров массивов и имён контейнеров после загрузки. prefabLabelLinks считает связи «метка — prefab», а не уникальные машины. Фракции, метки и пути сортируются по строковым ключам.

Конфиг сначала сохраняется по абсолютному пути, затем при необходимости регистрируется через RegisterResourceFile. Workbench создаёт .meta и GUID. Сборка использует PC; загрузка — MetaFile.GetResourceID(). Сериализуемые массивы не имеют инициализаторов `= {}`, поскольку они обнуляли результат CreateInstanceFromContainer; массивы для генерации создаются явно.
